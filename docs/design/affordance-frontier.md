# Affordance frontier (state → affordance → transition)

**Status:** Active — frontier in the packet, ranked action output, sibling retry.

A world model that knows only which objects exist is not enough for agency. To
choose a move the model has to know what can be done now, what each move is
expected to reveal, and which moves only become available after a probe. The
perceptor is therefore not a perceptor any more; it is a **multimodal
state–affordance–transition model**.

```text
screenshot
+ structural AX evidence
+ prior world document
+ observed CTA set          ─┐
+ one-step latent CTA graph  ├─ affordance_frontier
+ known transition edges    ─┘
+ last action result
        ↓
belief update
+ ranked next_actions[]
+ expected transition
+ missing affordance information
+ recommended probe
```

## Why it exists

The packet used to carry objects and their direct AX actions, and asked for a
single `likely_next_family` / `likely_next_target`. Two consequences:

- the model formed its latent world **before** seeing the full action frontier,
  and had to rediscover WhatsApp's interaction mechanics from pixels each frame;
- a richer candidate set appeared only later, in the action selector, so belief
  and action were conditioned on different views of the same screen.

Copying the old capability graph into the perceptor was not an option: it was
generated by cross-product rules and produced nonsense (`message →
InitiateVoiceCall`, `Apple → SearchConversation`) that would contaminate the
model's reasoning.

## Three classes, never merged

| Class | Meaning | Packet field |
| --- | --- | --- |
| observed | available right now, backed by AX or by the object inventory | `observed_actions` |
| latent | not on screen; names the trigger expected to reveal it | `latent_actions` |
| probe | unknown; worth taking for what it would reveal | `probe_actions` |

A latent `Forward` is never stated as an observed fact. Each latent entry
carries `available_now: false`, `available_after: <probe id>` and a
probability, so it reads as a reason to take the trigger rather than a control
to invoke. Probes carry `expected_information_gain`, which is what makes
"context-click first, it is more likely to expose Forward than hover" a
decision the model can make instead of a rule the runtime hardcodes.

Every entry carries `evidence` naming its source: `ax_action`, `ax_role`,
`vision_object`, `overlay_prior`, `interaction_prior`, `surface_graph`,
`transition_memory`. Provenance is the anti-pollution mechanism — a latent
action exists only because a source put it there.

## Where affordances come from

1. **AX** — role, label, bounds and supported actions for instantiated
   elements. Complete for chrome, silent about menus that do not exist yet.
2. **The model's own object inventory** — WhatsApp publishes no AX nodes for
   messages or chat rows, so without the previous document's `objects` a
   conversation would look like nothing but window buttons.
3. **Generic interaction priors** — keyed by object kind (`message → hover /
   context_click`, `row → open`, `input → type`). One small table, no
   cross-products.
4. **App adapter priors** — an overlay may implement `affordance_priors(surface)`
   and declare what only the app knows. WhatsApp declares the forward picker's
   `Send`, which no object prior could infer. The core never learns the menu tree.
5. **Transition memory** — what actually happened this session. Observation
   replaces prediction for the same `(action, surface)` pair, and the edge flips
   from `enumeration_status: predicted` to `observed`.

## Scope: one action deep, task-conditioned

Missing a relevant CTA hurts more than moderate redundancy, but shipping the
whole application's action space is what produced the polluted graphs. The rule
is the active surface plus one interaction beyond it, filtered by what can
advance the goal. Controls that are real but off-task (voice call, settings,
archive) go to `excluded_actions` **with a reason** rather than being dropped —
the model can see that the runtime considered and rejected them, and can
override from the screenshot if the exclusion was wrong.

An unrecognised goal gets no family filter at all: silently scoping a frontier
to the wrong task is worse than a wide one.

Transition edges are pruned the same way. The critic's opener sets are
unordered because it only asks "could this action explain the jump"; the
frontier has to answer "what gets me there", so only the strongest cause or two
per target surface is offered. A latent control is listed once, attributed to
its most likely trigger, rather than once per gesture that might reveal it.
Together this keeps the frontier around 5 KB of the packet.

## Ranked output, runtime-controlled search

The model returns up to three moves, best first, each with `confidence`,
`expected_progress`, `expected_information_gain`, `risk` and `reason`. The
runtime keeps the ones above threshold (`HERMES_ACTION_MIN_CONFIDENCE`,
`HERMES_ACTION_MIN_PROGRESS`), executes the top one, and falls to the next
sibling when the top is inadmissible — an unresolvable target or a family this
surface forbids. Discarding a considered ranking to re-ask the model is a step
spent on a question already answered.

The model proposes several actions; the runtime still owns admissibility,
permissions, execution, cycle detection, the irreversible gate and the step
budget. A ranked list never bypasses any of them, and if thresholds prune
everything the model's single best move is kept anyway — the gates below it
still stand.

`missing_affordance_information` closes the loop: the frontier is admittedly
incomplete for hover-only and custom-drawn controls, so the model reports what
it saw that the frontier failed to mention.

## Implementation

- `plugin/agent/affordance_frontier.py` — schema, sources, scoping, transition memory
- `_frontier_for_packet` in `unified_cognition.py` — assembly into the packet
- `_record_transition` in `unified_cognition.py` — the only place that sees both
  ends of an edge, so where prediction gets corrected
- `normalize_next_actions` / `ranked_action_candidates` — ordering and thresholds
- `_unified_fast_path` in `decision.py` — sibling retry
- `WhatsAppOverlay.affordance_priors` — app-declared latents

Toggle: `HERMES_AFFORDANCE_FRONTIER=0` removes the frontier from the packet; the
single-action output contract still parses, so the older shape keeps working.
